# Quantify Ambition

Preserve the size and character of the vision while making its implications explicit. The
goal is not to make the idea smaller or to decorate it with arbitrary KPIs. The goal is to
show what must become true, at what scale, with what resources, and how progress can be
recognized before the full vision exists.

## Principles

- Start from the change the project intends to cause, not from what it intends to build.
- Quantify only dimensions that affect strategy, feasibility, architecture, or impact.
- Separate known facts, researched benchmarks, estimates, targets, and open questions.
- Express uncertain values as ranges or scenarios, never as false precision.
- Show assumptions and calculations so the user can change them.
- Preserve non-commercial ambitions. Do not force revenue, growth, or startup vocabulary onto
  artistic, civic, scientific, open-source, or personal projects.
- Treat metrics as decision instruments, not as substitutes for judgment.

## Workflow

1. Frame the ambition.
   - Restate the vision, intended beneficiaries, desired change, scope, and time horizon.
   - Identify what makes the project ambitious: reach, technical frontier, coordination,
     capital, duration, behavioral change, or another dimension.
   - Surface material ambiguities. Ask a question only when different answers would change
     the thesis substantially; otherwise proceed with labeled assumptions or scenarios.

2. Build the quantification model.
   - Read [references/dimensions.md](references/dimensions.md).
   - Select the relevant dimensions rather than filling every category mechanically.
   - Define the units, relationships, constraints, and major unknowns.
   - Use dimensional reasoning and back-of-the-envelope calculations to expose consequences.

3. Ground the numbers.
   - Read [references/estimation.md](references/estimation.md).
   - Use project evidence and user-provided facts first.
   - Research current external facts and comparable systems when they would materially improve
     the model. Prefer primary sources and cite them close to the claim.
   - When evidence is weak, provide conservative, base, and ambitious scenarios rather than a
     single answer.

4. Create a metric tree.
   - Define one north-star outcome only when a single measure genuinely represents the vision.
   - Add leading indicators that can move before the final outcome is observable.
   - Add guardrails for qualities that growth or speed must not damage.
   - Connect outputs to outcomes with explicit hypotheses; shipping is not impact.
   - Define collection method, cadence, owner or source, and interpretation for each essential
     metric. Avoid metrics that cannot influence a decision.

5. Quantify the commercial thesis when generating income is part of the vision.
   - Read [references/commercial-viability.md](references/commercial-viability.md).
   - Identify the business shape before choosing metrics: SaaS, transactional product,
     marketplace, services, commerce, licensing, media, open-core, or a hybrid.
   - Connect customer value, distribution, pricing, retention, cost structure, and cash needs
     in one model. Do not analyze revenue in isolation.
   - If the project is not intended to generate income, skip this step entirely.

6. Stage the ambition.
   - Define successive proofs: desirability, feasibility, viability or sustainability, and
     ability to operate at the intended scale, as applicable.
   - Give each stage a question to answer, smallest credible evidence, resource envelope, exit
     criteria, and conditions for revising the thesis.
   - Do not present distant milestones with greater precision than current evidence supports.

7. Stress-test the thesis.
   - Identify the assumptions whose failure would invalidate the project.
   - Test capacity, cost, adoption, time, coordination, safety, and sustainability at the base
     and ambitious scales where relevant.
   - Find nonlinear thresholds: costs, staffing, regulation, reliability, or architecture that
     change category after a certain scale.
   - Include signals that should cause acceleration, redesign, reduction of scope, pause, or
     abandonment.

8. Deliver the quantified thesis.
   - Read [references/reporting.md](references/reporting.md).
   - Lead with the meaning of the ambition, then the numbers that define it.
   - Highlight the few variables that dominate the result and the cheapest next evidence that
     would reduce uncertainty.

## Boundaries

This is an analytical skill. Do not create project files, implementation plans, roadmaps in a
repository, budgets, issues, or external commitments unless the user separately requests
them. Do not imply that a target is a forecast or that an estimate is a researched fact.

Do not reject a project merely because its full vision is currently infeasible. Identify a
credible sequence of proofs and distinguish a difficult ambition from an internally
contradictory one.

## Completion standard

The result is complete when the user can see:

- what the ambition means in concrete terms;
- which numbers are facts, estimates, and choices;
- which assumptions dominate feasibility and impact;
- what evidence the next stage must produce;
- what success, unacceptable tradeoffs, and thesis failure would look like.

If available evidence cannot support meaningful numbers, say so and produce an explicit
measurement plan instead of fabricating targets.
